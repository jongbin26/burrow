# 파일 지도

코드 전에 "어느 파일이 무엇을 책임지는가"를 정하고, 그 뒤의 추가가 자리를 먼저 말하게 한다. 지도의 유지는 사람의 기억이 아니라 검사 스크립트가 한다. 검사가 없는 지도는 한 달 안에 어긋나고 그 뒤로는 아무도 믿지 않는다.

## 1. 새 디렉토리는 지도를 먼저 쓴다

코드를 쓰기 전에 그 디렉토리의 `README.md`(없으면 만든다)에 `## 파일 지도` 절을 두고 표를 쓴다.

```markdown
## 파일 지도

| 파일 | 책임 |
|---|---|
| `editor.ts` | 부품을 조립해 인스턴스를 만드는 facade. 로직 없음 |
| `snapshot.ts` | 조회 스냅샷 캐시. 레코드가 바뀐 경우만 다시 만듦 |
| `history/` | 역diff 스택 (안에 자기 README) |
```

- 책임은 한 줄, 명사형. 두 문장이 필요하면 파일이 둘이다 (cohesion 1·7)
- 하위 디렉토리는 `이름/`으로 한 행. 그 안에 README가 있으면 거기서 다시 지도를 쓴다
- 짝 파일(`*.test.ts`, `*.module.css`, `*.stories.tsx`)은 적지 않는다. 검사에서 `--pair`로 거른다
- 지도에 없는 파일을 만들 생각이면 표에 먼저 행을 더한다. 그 행의 책임이 기존 행과 한 문장으로 합쳐지면 파일을 만들지 않는다

## 2. 추가할 때 자리를 먼저 말한다

기존 디렉토리에 파일을 더하거나 기존 파일에 책임을 더할 때는 코드 전에 지도에서 자리를 가리킨다.

- 자리가 있고 그 행의 책임 문장이 그대로면 그 파일에 넣는다
- 그 행의 책임 문장을 고쳐야 들어가는 추가면 새 파일이다. 행을 더하고 만든다
- "기존 패턴을 따르는 추가"도 예외가 아니다. 지도가 심사의 입구다

## 3. 검사는 스크립트가 하고 lint 명령에 들어간다

`scripts/check-file-map.py`를 레포의 `scripts/`에 복사한다. 홈 디렉토리의 스킬 경로를 레포에서 참조하지 않는다. 다른 사람의 기기에는 그 경로가 없다.

```sh
python3 scripts/check-file-map.py packages/editor-core/src --pair '.test.ts' --pair '.module.css'
```

- 지도에 없는 파일, 파일이 없는 행을 출력하고 exit 1
- 레포의 lint 명령(예: `package.json`의 `lint` 스크립트)에 이 줄을 더한다. 넣지 않으면 절차가 끝나지 않은 것이다
- 디렉토리 여러 개면 명령을 나열한다. 스크립트는 한 디렉토리만 본다

## 위반 신호

- README에 지도가 있는데 lint 명령에 검사가 없다
- 지도에 없는 파일이 디렉토리에 있다, 또는 지도의 행이 가리키는 파일이 없다
- 책임 칸이 두 문장이거나 "그 외 유틸" 같은 잔여 범주다
- 새 파일을 만든 diff에 README 변경이 없다
- 레포 안 스크립트가 홈 디렉토리 경로를 가리킨다
