# 전역 스킬 만들기

전역 설정은 별도 레포(burrow)가 소유하고 각 도구 홈에는 심링크만 있다. 다른 레포에서 작업하다
호출되는 경우가 대부분이므로, **레포 위치를 먼저 찾는다.**

## 1. 레포 위치를 심링크에서 역추적한다

```sh
REPO=$(dirname "$(dirname "$(readlink "$HOME/.codex/AGENTS.md" 2>/dev/null || readlink "$HOME/.claude/CLAUDE.md")")")
```

경로를 추측하거나 하드코딩하지 않는다. `$REPO/manifest.txt` 존재로 검증한다.
링크가 없으면 아직 세팅 전이므로 사용자에게 알리고 멈춘다.

## 2. 무엇으로 만들지 정한다

| 성격 | 위치 | 로드 시점 |
|---|---|---|
| 요청이 있을 때만 필요한 절차·판정 기준 | `$REPO/src/skills/<name>/SKILL.md` | description 상시, 본문은 호출 시 |
| 조건 없이 항상 지켜야 하는 제약·개인 선호 | `$REPO/src/AGENTS.md` | 매 세션 전문 |

`AGENTS.md`는 모든 세션의 토큰을 먹는다. 기본은 스킬이다.

## 3. 스킬을 쓴다

- 디렉토리는 kebab-case, frontmatter `name`이 디렉토리명과 정확히 일치
- **description** — 상시 로드되는 유일한 부분. 150자 내외. 대상과 함께 좁게 쓴다
  (`"…를 만들거나 고칠 때, 그런 코드를 리뷰할 때"`). 트리거가 겹치는 스킬이 있으면
  상호 참조 한 줄을 넣는다
- **본문** — `규칙 + 한 줄 근거`. 끝에 `## 위반 신호`로 관측 가능한 신호를 나열한다
- 말미 Do/Don't는 본문과 중복이라 두지 않는다
- 판정할 수 없는 문장을 쓰지 않는다 (`"과설계도 결함이다"` ❌)
- 특정 조직·프로젝트에서만 통하는 규칙은 넣지 않는다 — 그건 그 프로젝트 문서로

## 4. 근거를 확인한다

규칙마다 왜 넣는지 답할 수 있어야 한다. 교과서 일반론으로 채우지 않는다.
외부 자료(노트·메신저·위키)가 근거면 **인용문을 파일 안에 옮겨 적는다** — 그 링크에 접근 못 하는
기기에서도 읽혀야 한다.

## 5. 마무리 — 링크를 묻는다

`src/skills/`는 항목 단위로 링크되므로 **새 스킬은 링크가 없어 도구가 인식하지 못한다.**

1. `$REPO/bin/doctor.sh`를 돌려 `MISSING` 목록을 근거로 보여준다
2. `$REPO/bin/link.sh` 실행 여부를 **사용자에게 묻는다**
3. 출력에 `backup`이 있으면 기존 실체를 치우는 중이므로 멈추고 알린다
4. 링크해도 **세션 재시작 전까지 로드되지 않음**을 안내한다
5. 커밋·푸시는 사용자가 한다

`AGENTS.md`에 넣은 경우는 파일이 이미 링크돼 있어 1~4가 필요 없다.

## 위반 신호

- 레포 경로를 문자열로 적어 넣었다
- description이 "…할 때 쓴다" 없이 기능 설명만 하고 있다
- 본문에 프로젝트 이름·사내 시스템·특정 패키지 경로가 있다
- 링크 안내 없이 "스킬을 만들었습니다"로 끝냈다
- 근거가 "일반적으로 좋은 관행이라서"뿐이다
