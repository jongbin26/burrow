# 함수형 프로그래밍

핵심은 순수성 자체가 아니라 **합성 가능성**이다.

## 1. 연산을 값으로 만들고 실행은 끝으로 미룬다

`Effect<A, E, R>`, `IO` 같은 타입은 결과가 아니라 **실행하면 결과가 나오는 명세**다.
명세와 실행이 분리돼야 재시도·타임아웃·취소·자원 정리를 바깥에서 붙일 수 있다.

- 실행 트리거(`runPromise`·`runSync`·`await`)는 **경계 한 곳**에만 둔다
- 중간 계층은 명세를 조립만 한다

## 2. 반복되는 분기는 문법이 아니라 합성으로 흡수한다

```
map     : (A => B)    => F[A] => F[B]
flatMap : (A => F[B]) => F[A] => F[B]
```

- 앞 결과를 봐야 다음이 정해지면 `flatMap`, 단계가 독립이면 Applicative로 충분
- null 체크·에러 전파·비동기·반복은 전부 `flatMap`의 다른 인스턴스다 — 각각 문법으로 풀지 않는다
- 결합법칙이 보장되므로 긴 체인을 분해·재조합해도 결과가 같다

## 3. 실패·의존성·비동기를 시그니처에 올린다

호출자가 반환 타입만 보고 무엇이 필요하고 무엇이 실패할 수 있는지 알아야 한다.

- 함수 안에서 전역·네트워크를 직접 잡지 않는다 — 잡으면 호출자가 대체할 수 없고 모킹도 막힌다
- `Promise`만으로는 의존성 주입도 동시성 제어도 표현되지 않는다

## 4. 의존성 수집과 부수효과 실행을 분리한다

자동 의존성 추적은 **실행해봐야 의존성을 안다.** 동기에서는 결정론적이지만 비동기 소스가 끼면
실행 횟수·순서가 비결정적이 된다.

- effect 안에서 실행 순서·횟수를 가정하지 않는다
- 비동기 파생값이 섞이면 UI는 한 시점의 **일관된 스냅샷**을 반영해야 한다 — 부분 갱신을 커밋하지 않는다

## 5. 변환은 원본을 보존한다

`map`·`filter`·`scan`이 새 값을 내놓기 때문에 체이닝이 성립한다. 불변은 목적이 아니라
합성을 가능하게 하는 전제다.

구독 생명주기를 직접 관리하는 모델(RxJS 등)은 **해제 누락이 곧 누수**다. 구독을 만든 쪽이 해제를
소유한다.

## 위반 신호

- 도메인·서비스 계층에서 `await`·`runPromise`가 호출된다 (실행이 안쪽으로 샘)
- `F[B]`를 돌려주는 함수가 `map`에 넘어가 `F[F[B]]`가 만들어진다
- 함수 본문에서 `fetch`·`localStorage`·`window`를 직접 참조한다
- 반환 타입이 성공값만 말하고 실패는 throw로만 표현된다
- `subscribe` 호출에 대응하는 해제 경로가 없다
- 같은 데이터를 매번 새로 만들지 않고 인자로 받은 배열·객체를 제자리에서 수정한다
