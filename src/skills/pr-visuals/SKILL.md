# PR 그림

글로 따라가기 어려운 흐름과 전후 차이를 그림으로 보여 리뷰어가 diff를 열기 전에 변경을 잡게 한다. 핵심은 여전히 본문 Markdown 텍스트에 두고 그림은 그 문단을 돕는다.

## 1. 업로드는 허용한 레포의 PR에서만 한다

그림은 사용자의 리소스 레포에 올라가고, 그 레포가 공개면 그림도 공개된다. 허용하지 않은 레포(회사 레포 등)의 PR에 그 주소를 실으면 내부 구조가 밖으로 나간다.

- 업로드 대상과 허용 목록은 기기별 설정 `${XDG_CONFIG_HOME:-~/.config}/pr-assets/config.json` 에 있다. 에이전트가 고치지 않는다
- 업로드 스크립트가 exit 3 으로 거부하거나 훅이 막으면 우회하지 않는다. 다른 호스팅, base64 data URI, gist 로도 올리지 않는다
- 허용하지 않은 레포에서는 그림 대신 Markdown 표, calldiff 같은 `diff` 블록, ` ```mermaid ` 블록을 쓴다. GitHub이 직접 렌더해 업로드가 필요 없다

## 2. 그림 하나에 요점 하나

PR 전체를 그린 그림 하나보다, 흐름 하나·전후 비교 하나·타이밍 하나를 각각 보여 주는 작은 SVG 여러 장이 읽힌다. 각 그림은 그것이 설명하는 문단이나 표 바로 아래에 둔다.

- 시간에 따른 변화(대기, 지연, 상태 전이, 단계별 흐름)는 반복 재생되는 CSS `@keyframes` 애니메이션으로 보여 준다. 읽는 사람이 언제 봐도 한 바퀴를 볼 수 있다
- 그림은 설명용이지 제품 코드가 아니다. 테스트를 쓰거나 화면 폭별로 따로 확인하지 않는다

## 3. SVG는 이미지로 렌더되는 것만 쓴다

GitHub은 본문의 SVG를 `<img>`로 띄운다. 스크립트, 외부 폰트·이미지, 클릭·호버·링크는 동작하지 않는다.

- 리소스는 모두 인라인으로 넣고 시스템 폰트 스택(`system-ui, -apple-system, "Segoe UI", sans-serif`)을 쓴다
- 너비를 고정하고 폰트 차이를 감안해 높이에 여유를 둔다
- 루트 SVG에 배경색을 두지 않는다. 투명하게 두어 GitHub 페이지 배경 위에 얹는다
- `@media (prefers-color-scheme: dark)` 로 다크 모드 색을 따로 준다
- 애니메이션은 CSS `@keyframes` 로만 만든다. SMIL, GIF, 동영상은 쓰지 않는다
- HTML 레이아웃이 필요하면 `<foreignObject>` 안에 인라인 `<style>` 을 둔 정적 XHTML을 넣고 `.svg` 로 저장한다

## 4. 스크립트로 올리고 출력된 Markdown을 그대로 붙인다

```sh
python3 "$HOME/.claude/skills/pr-visuals/scripts/publish-assets.py" \
  --asset flow.svg "저장 실패 시 흐름 전후 비교" \
  --asset timing.svg "재시도 타이밍"
```

- PR을 여는 레포 안에서 실행한다. 레포 밖이면 `--for owner/repo` 로 그 레포를 밝힌다
- 출력된 `![설명](...)` 줄을 해당 문단 아래에 붙인다. 주소는 커밋 고정이라 브랜치가 바뀌어도 깨지지 않는다
- 이미지가 아닌 MP4·MOV·WebM·HTML 은 링크로만 붙는다. HTML은 본문 안에서 실행되지 않는다
- 비밀 값, PR과 무관한 파일, 대화 내용은 올리지 않는다
- 붙인 뒤 PR 화면에서 그림이 보이는지 확인하기 전에는 확인했다고 쓰지 않는다

## 위반 신호

- 업로드 스크립트 거부나 훅 차단 뒤에 다른 경로로 그림을 실었다
- 설정 파일의 허용 목록이나 업로드 대상을 에이전트가 고쳤다
- 그림 한 장에 PR 전체 흐름을 담았다, 또는 핵심 내용이 그림에만 있고 본문 텍스트에 없다
- SVG에 `<script>`, 외부 폰트·이미지 URL, 루트 배경색, SMIL `<animate>` 가 있다
- 다크 모드 색이 없어 어두운 테마에서 글자가 사라진다
