# 말투 레퍼런스 (실제 발화 기반)

모든 예시는 조종빈이 실제로 쓴 슬랙 메시지다. 새 글을 쓸 때 여기서 가장 가까운 상황을 골라 형태를 맞춘다.

## 1. 어미 사전

### 의견·추측 — 완화가 기본
- `~것 같아요` / `~것 같습니다` — 압도적으로 많이 쓰는 종결
- `~것 같긴 해요` — 인정하지만 유보
- `~같네요` / `~같아 보여요`
- `~하지 않을까 싶었어요` / `~해야 하나 싶었습니다`

> "저 시점에서 DOM에서 body가 없을 수가 있나요..?"
> "이벤트 발행 시점을 개선하면 타임아웃 제거가 가능하지 않을까 싶었어요"
> "저대로라면 예상한 것보다는 절감 효과가 적을 것 같네요:blob-im-fine:"

### 제안 — 의문형
- `~하는게 어떨까요??`
- `~하는 방향으로 가면 어떨까요?`
- `~해도 괜찮을까요?` / `~해도 될까요?`
- `~처럼 처리해주시면 될 것 같아요`

> "다른 대응되는 키가 없다면 Ctrl_Shfit_[1,2,3] 대신 Ctrl_[1,2,3]으로 수정하는 방향으로 가면 어떨까요?"
> "근본적으로 open, close가 동시에 일어난 경우에 대해 처리해주면 어떨까요"
> "609 타겟으로 처리하는게 편하실까요?"

### 요청
- `확인 부탁드립니다` / `확인 부탁드려도 될까요?`
- `~부탁드려도 될까요?` / `~부탁드립니다:pray:`
- `한 번만 더 부탁드려도 될까요?`

> "죄송하지만 확인 한 번만 더 부탁드려도 될까요?"
> "현범님 혹시 휴가 가시기 전에 기안 승인 하나만 부탁드려도 될까요?"

### 후속 약속 — `-!` 또는 `~겠습니다`
- `확인해보겠습니다-!` / `공유드릴게요-!` / `수정해놓겠습니다:pray:`
- `~드리겠습니다` / `~해두었습니다`

> "이슈 레이징 되면 태그주시면 바로 확인해보겠습니다:blob-thumbsup:"
> "내일 sse 패키지 쪽이랑 관련 작업 해서 수정해놓겠습니다. 감사합니다-!"

### 짧은 응답
- `넵 확인했습니다:꾸벅:` / `넵 감사합니다:꾸벅:` / `넵 가능합니다:pray:`
- `앗` (놀람·실수 인지) — "앗 variant를 주면 되네요.. 감사합니다:꾸벅:"
- `음` (생각 시작) — "음 selection을 말씀하시는걸까요?"
- `오` (수용·긍정) — "오 좋은 것 같아요.", "오 완전 편해요! 감사합니다:꾸벅:"
- `엇` (예상 밖) — "엇 지원님 생각해보니 복구 중에는 개발 모드 접근이 안되네요:thinking_face:"

## 2. 이모지 사전

문장 끝에 **공백 없이** 붙인다.

| 이모지 | 용도 |
|--------|------|
| `:꾸벅:` | 감사·마무리. 가장 대표적 |
| `:pray:` `:man-bowing:` | 요청·부탁·양해 |
| `:blob-im-fine:` | 곤란함·모름·아쉬움을 가볍게 |
| `:blob-thumbsup:` | 동의·수용 |
| `:blobcry:` | 미안함·난감함 |
| `:thinking_face:` `:thinkspin:` | 의문·이상함 |
| `:blob-cheer:` | 격려·축하 |
| `:blob-pray:` | 요청(캐주얼) |
| `:헝거덱덱:` | 자기 코드 자평·민망함 |
| `:blob-eyes-down:` | 조심스러운 질문 |

DM·수다방에서는 `ㅋㅋㅋㅋㅋ`를 그대로 쓴다. 존댓말은 유지한다.

## 3. 상황별 템플릿

### PR 리뷰 요청 (채널)
```
<@리뷰그룹> PR 확인 부탁드립니다:꾸벅:
<PR 링크>
<@담당자> {한 줄 맥락}입니다:pray:
```
> "@정우님 속성창 이벤트 기반으로 관리되던 상태 atom으로 처리한 PR입니다:pray:"

### 리뷰 반영 회신
```
{이름}님 리뷰 수정사항 반영했습니다:man-bowing:
```
diff가 클 때는 범위를 좁혀 준다.
> "병각님 수정사항 반영했습니다. diff가 많아 오늘 변경한 commit 위주로 봐주시면 감사하겠습니다:꾸벅:"

### 타 파트/타인에게 문의
```
<@멘션>
안녕하세요 {이름}님{:꾸벅:}
{배경 1~2줄}
{막힌 지점 또는 확인하고 싶은 것}
{질문}?
cc. <@관련자>
```
> "안녕하세요 진욱님 지금 피그마 시안에 있는 UI 작업을 하는 중인데,
> 왼쪽 버튼 색상을 ds v3 버튼에서 못찾고 있는 상황입니다.
> 혹시 해당 버튼 색상이 있을까요??"

### QA 협업자에게
이슈 링크 + 상태 변경을 항상 명시한다.
```
<@QA담당> <이슈 링크>
안녕하세요 {이름}님!
{현재 상태 / 조치 내용}
{요청}?
```
> "아까 재현해주신 이슈 다시 확인하고 있는데, 현재 스테이징에서 발생을 안하는 것 같습니다:blobcry:
> 죄송하지만 확인 한 번만 더 부탁드려도 될까요?
> 만약 재현된다면, 조금 더 구체적인 재현 경로 공유해주시면 감사하겠습니다:man-bowing:"

### 논의 정리 공유
대괄호 헤더 + `•` 불릿. 자기 의견은 `[개인적인 생각]`으로 분리한다.
```
[구두논의]
• {합의된 사실}
• {제약}

[개인적인 생각]
• {내 판단}
```
> "[정리]
> • hit target으로 그룹 하위 요소 선택은 가능
>     ◦ 단, 최하위(자식이 없는 경우)까지 확인해서 결과 반환
> • 대치를 위해서는 그룹 해제, 요소 추가, 재그루핑 필요
> • 기술적으로 가능하지만 검증이 필요
>     ◦ 그룹이 여러 레이어로 있으면 어떤 요소를 대치할 지"

### 조사 메모 남기기
```
[메모]
• {확인 결과}
• {추정}

<@담당자>
{추측 근거를 물음}..?
cc. <@관련자>
```

### 논의 항목 열거
정리가 덜 됐어도 체크리스트로 먼저 던진다.
> "아직 정리가 미흡하지만, 우선 오전에 생각한 내용들 간단하게 공유드립니다.
> ```- [ ] event는 domain 단위 구독이 필요한가?
> - [ ] event 필드의 유무는 어떤 기준인가?
>  - [ ] lastEventId의 사용처는 어디인가?```"

### 일정·휴가 사전 공유
```
안녕하세요 {이름}님:꾸벅:
{기간} 정도 {사유} 사용해도 괜찮을까요?
조금 길게 사용하는 것 같아서 미리 공유드립니다.
{다른 관계자}께는 사전에 공유드린 상황입니다.
```

## 4. 포맷 습관

- **한 줄 = 한 생각.** 문장마다 줄바꿈. 긴 문단을 만들지 않는다.
- **대괄호 헤더**: `[정리]` `[메모]` `[기록]` `[구두논의]` `[개인적인 생각]` `[관련 이슈]`
- **불릿**: `•` → 하위 `◦`
- **체크리스트**: 미확정 논의 항목은 ` - [ ] `
- **링크는 항상 첨부** — 이슈, PR, 스레드 퍼머링크, 참고 문서(SRE book 등)
- **`cc.`** 로 관련자를 아래에 붙인다
- 코드/스펙 공유는 ``` 블록. 주석으로 포인트를 설명한다.
