# 개발 지식 스킬 템플릿

```markdown
---
name: <kebab-case, 디렉토리명과 같게>
description: <…할 때, …를 리뷰할 때 쓴다>. <무엇을 가리는지 나열>. <인접 스킬: 무엇은 X>
---

# <주제>

<이 스킬이 답하는 질문 한 줄>
<뿌리: 이 스킬이 기대는 메타 원칙. 한두 줄>

## N. <어느 레포에서든 지켰는지 가릴 수 있는 원칙 한 문장>

<왜 — 1~2줄>
<판정 질문 — 코드나 diff를 보고 답할 수 있는 질문 두 개 이하>

> 예: <이름을 지운 짧은 장면. 없어도 된다. 3줄 이내>

## 위반 신호

- <코드나 diff 에서 눈으로 확인되는 신호>
```

- 원칙은 스킬 하나에 7개까지, 파일은 80줄 안팎으로 둔다
- 끝에 Do/Don't 요약 절을 따로 두지 않는다
- 메타 원칙
  - MP1. 그 사실을 아는 쪽이 책임진다. 모르는 쪽으로 지식이 새거나 책임이 밀려오면 결함이다
  - MP2. 추정이 아니라 실제로 관측한 사실 위에 세운다. 모르는 것은 모른다고 드러낸다
  - MP3. 정책을 사람의 기억이나 손으로 맞추는 사본에 맡기지 않는다. 타입이나 single source of truth가 강제하게 한다
  - MP4. 구조는 꼭 필요하다고 증명됐을 때만 더한다. 엄격함은 그 코드가 얼마나 오래 쓰이는지에 맞춘다 (기본값)
