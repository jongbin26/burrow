# 개발 판단 목차

지금 하려는 행동 하나에 맞는 스킬을 골라 그 본문을 연다. 이 목차는 요약이 아니다. 고른 스킬을 읽지 않고 판단하지 않는다.
뿌리: 판단 기준은 기억이 아니라 그 순간 연 문서에서 온다. 행동이 바뀌면 이 목차를 다시 연다.

## 행동 → 스킬

| 지금 하려는 행동 | 열 스킬 |
|---|---|
| 파일·컴포넌트·함수를 가르거나 합친다, 크기·복잡도 한도에 걸렸다, 기존 파일에 기능을 더한다 | cohesion |
| 코드를 어느 모듈·레이어·패키지에 둘지 정한다, 의존 방향을 바꾼다, 외부 데이터를 어디서 검증할지 정한다 | module-boundaries |
| 새 디렉토리·패키지를 만든다, 파일이 많은 디렉토리에 파일을 더한다 | file-map |
| 래퍼·서비스·인터페이스를 새로 만든다, 이름을 짓거나 바꾼다 | abstraction |
| 상태·결과·실패·비동기의 모양을 정한다, 새 타입·필드·유니온을 만든다 | type-modeling |
| 버그 제보를 받았다, 재현했다, 회귀인지 가린다, 수정안이 원인을 없애는지 본다 | root-cause |
| 변경을 어디까지 넣을지, 고치는 김에 더 고칠지, 이전 데이터와 호환할지 정한다 | change-scope |
| 테스트를 쓰거나 고친다 | write-test-code |
| 관측 이벤트·에러 계측을 더한다 | observability |
| 실행 계획을 여러 PR로 나눈다 / PR·커밋 메시지를 쓴다 | pr-slicing / pr-writing |
| 끝났다고 보고하거나 커밋하기 직전이다 | readability-pass |
| 사용자가 판단 기준을 말하거나 에이전트 판단을 고쳐 준다 | dev-core-update |

그 기술로 짠 코드라면 위 스킬과 함께 연다: react, typescript, rxjs, effect.

## 고르는 법

- 행동이 여럿이면 지금 바로 할 행동 하나부터 연다. 다음 행동으로 넘어갈 때 다시 고른다
- 검토·리뷰 요청이면 그 diff가 하는 행동(가르기, 새 타입, 경계 이동)마다 해당 스킬을 연다
- 버그 수정이라도 원인 찾기(root-cause)와 테스트(write-test-code)는 연다

## 위반 신호

- 목차만 열고 짚힌 스킬 본문을 열지 않았다
- 작업 도중 행동이 바뀌었는데(가르기 → 버그 → 테스트) 목차를 다시 열지 않았다
- 린트·테스트 통과만 근거로 완료를 보고했다
