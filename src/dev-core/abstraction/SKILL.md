# 추상화와 이름

이 레이어를 지금 만들어야 하나? 만든 추상화는 진짜인가? 이름은 하는 일을 그대로 말하나?
뿌리: 구조는 "꼭 필요해?"에 답할 수 있을 때 더한다. 오래 갈 코드는 엄격하게, 금방 버릴 코드는 가볍게 간다. 둘 다 기본값이고, 벗어날 때는 이유를 말할 수 있으면 된다.

## 1. 레이어는 필요한 근거가 지금 보일 때 만든다

래퍼를 하나 두면 읽는 사람은 indirection을 한 단계 더 따라가야 한다. 실제로 갈리는 구현체, 두 번째 사용처, 실제로 줄어드는 보일러플레이트 중 하나도 없으면 비용만 는다. 가상의 요구사항으로 만든 레이어는 성급한 추상화다.
예외는 확장 대상이 요구사항에 명시돼 있거나, 같은 분기가 이미 여러 곳에 반복될 때다. 이때는 먼저 추상화해도 된다. 미루면 분기만 쌓인다. 예외를 쓰려면 그 근거를 코드나 문서에서 가리킬 수 있어야 한다.
판정 질문: 이 레이어를 지우면 지금 무엇이 깨지거나 반복되지? 갈라질 거라는 근거가 코드나 요구사항에 있나, 내 예상에만 있나?

> 예: 상태 값 하나를 감싸기만 하는 함수가 있어서 값을 보려면 indirection을 두 번 따라가야 했다. 보일러플레이트를 실제로 줄여 주는 래퍼만 남겼다.

## 2. 안 쓰이는 레이어와 상태는 제거한다

만든 근거가 사라졌거나 처음부터 가상이었다면 남길 이유가 없다. 안 쓰이는 구조도 주변 상태와 분기를 붙잡고 있어서 다음 변경을 무겁게 한다.
사용처가 하나뿐이면 인라인하고, 재사용이 생기면 다시 추출한다.
판정 질문: 이 레이어나 필드, 옵션을 실제로 쓰는 곳이 있나? 지우면 같이 사라지는 상태가 있나?

> 예: 미래 대비로 넣은 식별자, 한 곳에서만 쓰는 전용 클래스, 세 겹 accessor를 제거했다.

## 3. 추상화했다면 구현 차이가 정말 캡슐화됐는지 본다

사용처가 여전히 직접 조립하거나, 추상화 내부에서 결국 구체 타입별로 분기하거나, 겉 이름만 바꿨다면 구현 차이는 캡슐화되지 않고 자리만 옮겼다. 이런 건 가짜 추상화다.
상위 타입이 하위 타입을 이름으로 알고 있는 것도 같다. 의존 방향이 거꾸로다.
판정 질문: 사용처가 구체 타입을 몰라도 쓸 수 있나? 추상화 내부에서 구체 타입으로 분기하고 있지 않나?

> 예: "시각화"라는 상위 타입의 표시 판단이 하위 타입인 차트와 다이어그램을 이름으로 나눠 처리했다.

## 4. 네이밍은 책임 전체를, 실제 사용 범위만큼 드러낸다

특정 기능에 결합된 코드에 범용 이름을 달면 다른 사람이 재사용한다. 반대로 좁은 이름은 이미 넓어진 쓰임을 숨긴다. 하는 일의 절반만 말하는 이름도 같다.
판정 질문: 이 이름의 사용처를 모두 찾아봤을 때, 이름이 말하는 범위와 실제 쓰임이 같은가? 구현을 다 읽어야만 하는 일을 알 수 있지 않나?

> 예: 특정 표의 업무 로직에 묶인 함수가 범용 이름을 달고 있었다. 반대로 한 속성 이름을 단 모듈이 실은 같은 종류 입력 전반을 다뤘다.

## 5. 이름에 구현 상세를 넣지 않고, 동작이 바뀌면 이름도 바꾼다

구현 기술이나 개수가 들어간 이름은 구현이 바뀌는 순간 틀린다. 로직이 다른 곳으로 옮겨 갔는데 이름이 그대로면 읽는 사람은 옛 동작을 믿는다.
판정 질문: 구현을 교체해도 이 이름이 맞나? 이번 변경 뒤에도 이름과 하는 일이 같나?

> 예: 복사 로직이 서버로 옮겨 갔는데 클라이언트 함수 이름은 여전히 복사를 말했다. "네 칸 배치"라는 이름은 칸 수가 바뀌면 틀린다.

## 6. 처음 보는 사람이 위에서 아래로 쭉 읽게 둔다

분리는 이해를 돕는 만큼만 한다. 작은 함수로 잘게 나눠 시선이 위아래로 오가면 분리가 오히려 비용이다. 깊은 조건 중첩도 흐름을 가린다.
판정 질문: 한 곳에서만 쓰이는 짧은 헬퍼를 인라인하면 더 읽기 쉬워지나? 조건 중첩을 early return으로 펼 수 있나?

## 7. 주석은 코드만으로 알 수 없는 "왜"만 단다

코드만으로 이해가 되는데 주석이 있으면 읽기만 느려지고 언젠가 코드와 어긋난다.
반대로 읽다가 의아할 자리에 이유가 없으면 다음 사람이 같은 조사를 다시 한다. 이슈 때문에 건너뛰는 분기, 정책, 외부 동작을 알아야 이해되는 코드가 그런 자리다.
판정 질문: 이 주석을 지우면 잃는 게 있나? 읽다가 의아할 자리에 이유가 붙어 있나?

## 위반 신호

- 사용처나 구현이 하나뿐인 인터페이스나 래퍼가 새로 생긴다
- 레이어나 필드, 옵션을 둔 이유가 "나중에 필요할 수도 있어서"뿐이다
- 상위 타입이나 공용 함수 안에서 구체 타입으로 분기한다
- 추상화를 들였는데도 사용처마다 같은 조립 코드가 반복된다
- 이름에 구현 기술이나 개수가 들어 있다. 또는 동작이 바뀐 diff에서 이름은 그대로다
- 몇 줄짜리 처리가 작은 함수 여러 개로 흩어져 있다
- 코드를 다시 말하는 주석이 있다. 또는 이유 없이 건너뛰는 분기가 있다
